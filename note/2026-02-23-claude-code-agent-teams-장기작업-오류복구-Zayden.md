# Claude Code Agent Teams로 장기 작업 오류 복구 문제 해결하기

Claude Code 단일 세션에서 프로세스 실행 중 에러가 발생하면 작업이 멈춰버리는 문제가 있다. Agent Teams 기능을 활용하면 감독자가 작업자의 에러를 감지하고 복구할 수 있어 장기 작업이 가능해진다.

## 문제

- Claude Code (2.1.50 기준) 단일 세션에서 에러 발생 시 작업 중단
- 장기 작업이나 오류 복구 시 사용자가 일일이 간섭해야 함
- 빌드 실패, 테스트 에러 등에서 자동 복구가 안 됨

## 해결: Agent Teams 감독자 + 작업자 패턴

공식 문서: https://code.claude.com/docs/en/agent-teams

### 핵심 아이디어

**감독자(Lead) 1명 + 작업자(Teammate) 1명** 구성으로 운영한다.

- 작업자가 에러로 중단되면 감독자가 idle 알림을 수신
- 감독자가 작업자에게 수정 지시를 보내거나 새 작업자를 생성
- 각 세션이 독립 컨텍스트 윈도우를 가져 에러가 전파되지 않음
- 공유 작업 목록(Task List)으로 전체 진행 상황 추적

### 복구 흐름

```
[작업자] 빌드/테스트 에러 발생 → 작업 중단
   ↓
[감독자] idle 알림 수신 → 에러 확인
   ↓
[감독자] 작업자에게 수정 지시 전송 또는 새 작업자 생성
   ↓
[작업자] 지시 수신 → 작업 재개
```

## 설정 방법

### 1. 기능 활성화

실험적 기능이므로 `settings.json`에 명시적 활성화 필요:

```json
{
  "env": {
    "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1"
  }
}
```

### 2. 팀 생성

자연어로 지시하면 된다:

```
이 작업을 위한 에이전트 팀을 만들어줘.
감독자 1명, 작업자 1명으로 구성하고,
작업자가 에러를 만나면 감독자가 복구 지시를 내려줘.
```

### 3. 디스플레이 모드

| 모드 | 설명 | 비고 |
|------|------|------|
| `in-process` | 메인 터미널에서 Shift+Down으로 전환 | 기본값, 별도 설정 불필요 |
| `tmux` / `iTerm2` | 각 팀원이 별도 패널에 표시 | tmux 또는 iTerm2 필요 |

## Subagent와의 차이

| | Subagent | Agent Teams |
|---|---------|-------------|
| 통신 | 결과만 메인에 반환 | 팀원 간 직접 메시지 |
| 에러 복구 | 메인 세션이 직접 처리 | 감독자가 작업자에게 복구 지시 가능 |
| 컨텍스트 | 메인 세션 내부에서 실행 | 완전 독립 컨텍스트 윈도우 |
| 장기 작업 | 메인 세션 컨텍스트에 종속 | 독립 세션으로 장기 작업에 유리 |

## Hooks로 품질 게이트 강화

- `TeammateIdle`: 작업자가 idle 될 때 실행. exit code 2로 피드백을 보내 작업 계속 유도
- `TaskCompleted`: 작업 완료 시 실행. exit code 2로 완료를 막고 추가 검증 요청 가능

## 주의사항

- **토큰 사용량 증가**: 각 팀원이 독립 컨텍스트를 가지므로 단일 세션보다 소모 많음
- **세션 복원 불가**: `/resume`, `/rewind`로 in-process 팀원 복원 안 됨
- **한 세션에 한 팀**: 동시에 하나의 팀만 관리 가능
- **파일 충돌 방지**: 같은 파일을 여러 작업자가 동시 편집하지 않도록 역할 분리 필요

## 실전 팁

- 감독자에게 명확한 복구 전략을 지시: "작업자가 에러로 멈추면 에러 로그를 확인하고 수정 지시를 보내줘"
- 작업자당 5~6개 태스크를 유지하면 재배분도 용이
- 위험한 작업은 `plan approval`을 요구하여 감독자가 계획 승인 후 실행
- 사전에 권한 설정을 해두면 팀원의 permission 프롬프트를 줄일 수 있음

## 결론

단일 세션의 에러 중단 문제는 Agent Teams의 감독자+작업자 패턴으로 해결할 수 있다. 감독자가 상시 모니터링하며 에러 복구를 자동화하므로, 사용자 간섭 없이 장기 작업을 안정적으로 수행할 수 있다. 다만 실험적 기능이므로 세션 복원 불가 등의 제약은 감안해야 한다.
